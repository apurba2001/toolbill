Deliverable 1

Toolbill design system

Material 3 tokens, type scale and component states for the Android app. Every value below maps 1:1 to a Compose ColorScheme / Typography entry.

IBM Plex Sans / IBM Plex Mono
4dp spacing base
360dp baseline width
Assumption

Hierarchy is carried by type size and 1px dividers. Cards are used only where content is genuinely a separable object — the FX notice and the paywall plans. Everything else is a flat surface on surface.

Accent discipline

Amber is the only accent: FAB, primary buttons, selected states, and the due-soon window. Red is reserved for overdue and destructive confirmation. Teal appears only on trials.

Numbers

All money is IBM Plex Mono with tnum on, so decimals column-align in a 35-row list. Currency codes sit at 11sp, muted, never bolder than the figure.

Normalized monthly

Every sort, every total and every list runs on amount × (365.25 / cycleDays) / 12. An annual ₹4,662 plan is ₹388.50 a month and ranks there. Raw charge amounts survive only in the calendar, the due list and the CSV — the three places where the real number is the point.

Currency notation · one rule

ISO code labels the hero figure and the detail header — INR 44,170.50. The ₹ symbol goes inline in rows, chips, badges, footers, captions and widgets. Never a code and a symbol in the same figure. In an aligned amount column the currency is declared once in the column head and never repeated per row, so the digits stay in a single tabular block. INR uses Indian digit grouping: ₹5,30,046, not ₹538,398.

Money/Hero autosize

45sp fits ~11 characters at 360dp. High-denomination currencies routinely exceed that, so the hero style steps down instead of truncating.

Density note

Rows are 52–56dp: name at titleMedium, one 11sp support line, amount right-aligned in tabular mono. No leading avatar in the dense list — the 32dp monogram only appears on Home's next-7-days list, where there are at most five rows. That buys three extra rows per screen and keeps the amount column at a fixed x.

Business/personal is a single mono B / P glyph in the support line rather than a coloured chip — with 35 rows, 35 chips is noise, and the filter chips above already carry the colour.

Sorting is a SegmentedButton, not a menu: three options, always visible, one tap. Long-press a row for a ModalBottomSheet with mark paid / pause / duplicate / delete.

Next 7 days lists all eight charges rather than truncating at four. A “+4 more this week” affordance would hide ₹7,506 — more than half the week's money — behind a tap, and the one number this block exists to justify would stop being checkable on screen. Home scrolls; the frame above is drawn tall to show the whole list, the way the 35-row list is. The footer repeats the total so the arithmetic closes in view.

Non-monthly rows carry two figures: the normalized monthly is primary, the real charge sits under it as ₹4,662.00 · USD 54.99. Monthly rows keep one figure, so the second line appears only where it changes the ranking.

The currency is declared once in the column head — ₹ / month — not repeated on 35 rows, which keeps the digits in one tabular block.

contentDescription: the B/P glyph reads “Business expense” / “Personal”; each badge reads its full state and timing (“Overdue by 2 days”, “Trial ends in 6 days”); the amount reads “₹388 fifty paise per month, billed annually as ₹4,662”. A one-time tooltip anchored to the first B glyph introduces it, dismissed on tap and never shown again.

04 — Add / edit subscriptionModalBottomSheet, skipPartiallyExpanded = false.

Why a sheet, not a full screen: adding is a repeated, low-commitment act — a user entering their fifth tool in a row should never lose sight of the list. The sheet keeps the back gesture cheap (swipe down = discard, no dialog when nothing was typed), reaches 92% height when the keyboard is up so it functions as a full screen when it needs to, and lets the required fields — name, amount, cycle — sit above the fold with the keyboard open. Edit reuses the same sheet with values pre-filled and a Delete text button in the header. The one exception: custom billing cycle pushes a nested sheet rather than growing this one.

Speed decisions

Name field is focused on open, keyboard already up. A local catalogue of ~400 common SaaS names pre-fills name, currency, billing cycle and category — shipped in the APK, no network.

It never pre-fills the amount. Bundled prices go stale within months, and a silently wrong amount corrupts the burn total permanently, because nobody re-checks a field that was already filled. Focus lands on the empty amount instead — the one number only the user's invoice knows.

Currency defaults to home currency, but flips to the last currency you used for a business entry, since these users mostly pay USD.

First charge offers Today / next 1st / DatePicker — three taps saved for the common case. Category, notes and trial date are progressive: hidden behind text buttons so the required path is four fields long.

Save & add another keeps the sheet open and resets only name and amount — the pattern that gets someone from zero to thirty entries in one sitting.
